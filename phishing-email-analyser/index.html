What this checks

  • Language: urgency, threats, requests for passwords, MFA codes, payments, gift cards and bank-detail changes
  • Links: look-alike domains (including Unicode homographs and Punycode IDNs), shortened links, raw IP addresses, "@" tricks and misleading link text
  • Attachments: executables, double extensions, macro documents and "Enable Content" requests
  • Sender: SPF/DKIM/DMARC failures, Reply-To mismatches and fake display names
  • Voice calls: impersonated banks and IT staff, "safe accounts" and remote-access requests

Privacy & how it works

Your email never leaves this page

All analysis is done by JavaScript running inside your browser tab. There is no server, no AI service, no analytics and no tracking. The page includes a Content Security Policy that forbids it from connecting to any server at all, so even a bug could not upload your text.

You can check this yourself: open your browser's developer tools (F12), go to the Network tab, and click Analyse. No new requests appear. You can also disconnect from the internet and the analyser keeps working.

What is stored

If you leave the checkbox ticked, the analyser saves a small summary of each analysis in your browser's local storage: the date, the score, and the names of the warning signs. It never saves the message itself. Challenge answers and training progress are stored the same way. Use the button below to delete all of it.

Incomplete scans and copied email headers

Long messages, oversized tokens and complex MIME files are subject to processing limits to prevent resource exhaustion. When not all content could be inspected, the report displays an explicit warning. SPF/DKIM/DMARC strings pasted from an email are unverified header claims, not proof of authentication; confirm them through the trusted receiving mail provider.

How the score works

Each warning sign has a weight that reflects how strongly it predicts phishing. A password request counts far more than a generic greeting. Signs that are much more dangerous together, such as a credential request plus a fake link, add a bonus. The total is converted to a 0–100 scale: Low (0–19), Medium (20–44), High (45–69), Critical (70–100).

Unicode homograph / brand impersonation checks

The enhanced investigator inspects locally submitted QR image content when a decoder is available, checks HTML destination attributes, uses a bundled Public Suffix List snapshot, decodes internationalized domain names and checks for selected visually confusable Unicode characters, unusual script mixing, spoofed trusted-domain fragments, and deceptive hosted subdomains. When it finds a brand lookalike, the report identifies Unicode code points and explains the trust-boundary mismatch. International characters and Punycode are not inherently dangerous. The implementation uses a wider ICU-derived confusable mapping with audited overrides and an optional updater for current Unicode UTS #39 data. It does not claim full Unicode UTS #39 conformance. It cannot establish who registered a domain or what a website contains.

Limits

This is a rule-based teaching tool, not a security product. It can miss well-crafted attacks and can flag legitimate messages. It never visits links, so it cannot see what a website actually contains. A low score is not proof that a message is safe. When in doubt, verify through a channel you trust and report it to your security team.
